# 表单架构自动化可行性审查

日期：2026-10-26。基线：0.25.3，源码提交 `63f567c`。

## 结论

当前适合作为**用户核对后的辅助填写工具**，尚不能作为任意招聘站通用、无人值守的填表 Agent。可行性取决于“字段可发现、归属可确定、选项可操作、结果可回读”四个条件，不能仅凭识别出字段文字判定可自动化。iframe 是文档边界，Moka 是产品及其组件结构，两者不是互斥架构。

本次审查检查本地源码并运行合成页面测试，没有登录真实招聘站、填写个人资料、保存简历或提交申请。历史 Moka 真实页面的结构观察不等于本轮在线复测。所有回归通过也不代表所有站点支持。

## 架构与控件矩阵

| 场景 | 当前实现/验证 | 自动化结论与限制 |
| --- | --- | --- |
| 普通 DOM：input、textarea、select、radio | 标签/位置/表格归属、原生赋值和事件、精确选项、回读有回归 | 可辅助填写；仍需排除缺失资料、歧义、网站校验 |
| React/Vue 等受控组件 | 原生 setter + input/change，部分组件点击真实菜单并等稳定回读；测试模拟异步重置 | 有条件支持，不等于验证了所有框架版本。事件要求 `isTrusted`、特殊编辑器状态或重绘替换可能失败 |
| 可见同源 iframe | 按 frameId + documentId 路由，版本、URL、文档变化检查；安装扩展回归 | 单个有效表单可用；刷新后必须重扫，不会沿用旧文档 |
| 嵌套同源 iframe | 新增真实 DOM 探针确认两层框架路由 | 有条件可用；探针的 Chrome 扩展 API 为模拟接口，实际扩展嵌套覆盖尚不足 |
| 跨域 iframe | `page-bridge.js` 明确按与外层相同 origin 过滤；跨域祖先可见性检查也会拒绝 | **当前不支持**。即使拥有注入权限也不会路由。扩展逐域授权及分文档执行在设计上有可行性，不是浏览器永远禁止 |
| srcdoc / about:blank iframe | 子文档能识别字段，但路由仅接受 HTTP(S) URL | **当前不支持**；继承 origin 也不会越过 URL 筛选 |
| 隐藏 iframe / 字段 | 可见性与祖先检查，已有扩展回归和新增探针 | 刻意排除，避免后台/旧步骤误写；需用户先展开当前步骤 |
| 同页多个表单文档 | 多个候选时明确停止 | 可发现，但无文档选择 UI；需单独打开目标文档，不会选择第一个 |
| 开放 Shadow DOM | 扫描使用普通 querySelectorAll，不递归 shadowRoot；探针确认零字段 | **当前不支持**；开放根可增加受控遍历与根内归属规则 |
| 封闭 Shadow DOM | 普通扫描无法进入，探针确认零字段 | 当前不支持；不承诺靠 OCR 或 AI 可直接填写。可能需要可访问性/浏览器输入工具或人工 |
| Moka sd-Select 普通及年月菜单 | 同时处理外层普通选项和直接菜单项，读取提交显示值，年月拆分有回归 | 已覆盖观察到的结构；依赖散列类名前缀和特定模块布局，远端搜索、地区和日历不可一概宣称支持 |
| Moka 出生日期/只读地区 | 代码明确提示手动操作；不直接改写只读框 | **仍需专用适配**；不是所有 Moka 控件已实现 |
| Moka 模块语义 | 专用规则识别个人/教育/工作/实习/项目/获奖/家庭 | 求职意向、语言能力等未知模块可能 contextBlocked，使 AI 候选也被阻断 |
| Layui | 同时核对原生数据源与显示值；重绘绑定、延迟清空和批量联动有回归 | 已适配结构可用，其他变体仍需验证；没有依赖只改可见文本伪造选中 |
| Ant/Element/ARIA 下拉与 portal 浮层 | ARIA 关联优先，候选可见/可用/唯一检查；异步等待及归属回归 | 有条件支持；没有稳定归属或不同菜单同时打开时应停止 |
| 虚拟列表 | 完整索引、总数与候选完整性检查，最多 500 条/40 页 | 完整索引支持；已识别但缺索引的虚拟列表转人工。不能把“当前可见唯一”当全表唯一 |
| 省市区/51job 多级引用选择器 | 唯一末级或明确完整路径、逐层操作及选中路径核验有回归 | 已适配结构可用，不是任意树/滚轮/多选级联通用支持；地区词典有版本时效边界 |
| 日期 | 原生日期、年月拆分、显式配置的日期面板有回归 | 保留精度、不虚构月日；通用只读日历需要适配。按月翻页可能慢，默认最多 600 次 |
| 动态步骤/经历卡片/弹窗 | 重扫、区块限定、记录隔离；新增/编辑/保存经历须站点适配 | 有条件支持；不是自动导航所有步骤，区块模式不自动新增保存卡片 |
| contenteditable | 简单 DOM 扫描探针；写 textContent + InputEvent | 简单可编辑区有路径；Quill/ProseMirror 等富文本模型未作通用验证，不能据此宣称支持 |
| Canvas/图片表单、OCR | OCR 是标签补充；仍依赖可定位 DOM 控件；iframe 截图 OCR 显式拒绝 | 不具备纯视觉坐标执行器，不能靠 OCR 将 Canvas 表单自动化 |
| 文件、复选框、验证码、密码、同意与提交 | 文件/checkbox 等扫描排除，敏感题与提交受保护 | 本就不是完整申请工作流；普通技能多选复选框也会被排除，不仅法律同意框 |

## 已复现及优先处理项

### P1：工作与实习可能复用同一条本地经历

Moka 的“工作经历”“实习经历”各自从当前模块的第 0 张卡片起算，但都映射到 `work`。新增探针将两模块的“公司名称”都匹配到 `work.0.company`。重复字段警告的分组键包含 context，两模块 context 不同，因此不能阻止这次复用。**这是已复现的错配风险，不是未识别。**

建议先加入跨模块记录分配/冲突检查，资料带工作类型时按类型分组；类型不明确时让用户选择起始记录，禁止默认双用。本次只审查，没有修复这项生产逻辑。

### P1：零字段不能说明页面没有表单

跨域、srcdoc 和 Shadow DOM 探针中，字段确实存在，但没有进入当前扫描结果。此时没有字段 ID/候选传给 AI，模型无法“主动补救”。建议扫描回执增加排除原因及计数，并在 UI 显示“不支持的嵌入文档/Shadow 控件”，区分没有表单、权限不足与尚未适配。

### P2：Agent 是受控状态机，不是自主浏览器操作规划器

`local-server/agent.cjs` 只提供 observe_page / match_fields / fill_fields / verify_fields 四种工具。模型主要提出已有路径建议；工具异常会 needs_input，缺少资料也需核对。contextBlocked、歧义和无候选字段不会进入 match_fields。现有语义校验和隐私边界应保留，但它们也说明“启用 AI”不能弥补未扫描到的控件或未实现的执行器。

建议增加结构化失败类别和有限恢复策略：文档变化重扫；异步候选再等一次；上级联动完成后重取控件；超限停止。模型可以在已实现工具中选择策略，不允许生成任意 JS/选择器直接执行，也不允许自动扩展填写范围。

### P2：缺少服务端持久化验证

稳定回读的默认窗口约 900ms，整个选择稳定等待上限约 2600ms，批次后也有回读。这只能证实当时 DOM 状态，不能证明服务端接受。较晚异步清空、刷新后丢失、后端校验仍可能发生。未来需要专门的合成延迟场景与用户明确保存后的状态核验，不把提交申请作为测试手段。

## 分阶段建议

1. 先防错：修复工作/实习记录复用；补充扫描排除原因、文档/控件能力清单。
2. 再扩大覆盖：开放 Shadow DOM、iframe 文档选择、srcdoc 路由；跨域逐域授权并确认目标文档，保留刷新与 origin 校验。
3. 再补执行器：Moka 只读日历/地区、远端搜索、联动重绘；用现有选项 ID/完整路径执行并核验。
4. 最后增强 Agent：观察 → 判断失败类型 → 从白名单策略恢复 → 独立回读；不能稳定验证或有事实歧义时交回用户。
