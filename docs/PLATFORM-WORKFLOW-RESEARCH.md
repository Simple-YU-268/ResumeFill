# 三平台工作流静态研究

采集日：2026-11-12。研究对象为职悟空安装包 0.1.32 与其公开工作流清单所指向的三个 JavaScript 模块。本文是静态观察，**不是实站验证或兼容性承诺**。没有执行或导入竞品模块，没有调用其业务后端，也没有读取真实用户资料、凭据或账号信息。

## Moka

主流程（4129–4227）：检查职位入口 → 监听用户完成 → 读取资料 → 首次识别 → 发现上传控件 → 优先上传用于解析的简历 → 等待解析并重新发现上传控件 → 处理其他附件 → 填写字段 → 非侵入式回读并生成核对结果。工作流的 `completed` 仅表示填表阶段结束，不能当作投递成功。

| 页面事实 | 静态依据 |
| --- | --- |
| 表单块类名前缀 `apply-blocks-` | 3509–3513 |
| 重复记录容器前缀 `apply-fields-`；字段前缀 `apply-field-` | 3522、3531 |
| 字段标题前缀 `title-`；控件容器前缀 `ctrl-` | 3773–3776 |
| 自定义选择器前缀 `sd-Select-container-`；选项前缀 `sd-Select-common-item-` | 3230–3234 |
| 导航中的登录入口、账号区域分别使用 `login-btn-`、`account-` 前缀 | 4267–4295 |
| 预览确认区域 `.apply-form-preview .btn-ok`，完成页候选前缀 `apply-thanks-` | 2822、2837–2842 |

这些是类名 token 的前缀事实，不能用任意属性子串匹配代替 token 校验。重复记录需保留所属区块与记录序；不能把整个页面同名字段按全局顺序混填。

上传解析会替换 DOM、增加记录或改变控件。独立实现应废弃上传前元素引用，待局部稳定后重新扫描、匹配身份并回读已选项；解析完成前不要立即覆盖其输出。竞品识别阶段还会主动选择“有经历”来展开字段（3730–3799），我们的扫描必须保持只读，将此类选择放入经用户核对的执行计划。

登录检测中存在“未发现登录按钮便视为已登录”的推断（4253–4316），不足以证明有效会话。职位可用性也仅以申请按钮是否存在推断（4421–4452），骨架屏、布局变化、权限页都可能造成误判。产品应保留 `unknown`，仅凭明确关闭文案判定关闭。成功候选也必须同时满足当前可信来源、用户确实触发最终提交、可见成功状态；不能因为预览消失就宣告失败或成功。

## 北森

主流程（6280–6444）：验证目标并进入申请表 → 分类登录、关闭、投递限制等状态 → 识别重复区块 → 首轮扫描及上传控件发现 → 简历解析上传 → 等待解析与表单稳定 → 重新发现上传控件 → 其他附件 → 填写 → 不再打开下拉的最终回读。竞品存在自动对齐记录数量的步骤；我们的新增记录应由计划明确列出，禁止为了“对齐”删除用户记录。

| 结构/状态 | 可独立使用的事实与行号 |
| --- | --- |
| 表单根 | `.form-root, [class*="STFormContainerRoot"]`（1804–1807） |
| 登录根候选 | `[class*="STFormWraper"]`（1807）；应结合 `/login` 与可见登录控件，避免仅凭 CSS 判定 |
| 重复记录卡片 | `.ux-standard-form`（2426）；同模块内容容器内的卡片排列构成记录序（2430–2432） |
| 字段根 | `.form-item`（2433） |
| 字段标题 | `.form-item__text`，后备 `.form-item__title`（2437） |
| 必填标记 | `.form-item__required`（2440） |
| 模块标题 | 没有发现固定模块标题选择器；竞品由卡片向上找祖先，检查最多六个前兄弟节点，以短文本且不含 `.form-item` 的语义标题建立上下文（2189–2206） |
| 普通下拉列表/选项 | `.phoenix-selectList` / `.phoenix-selectList__listItem`（2270–2364） |

| 地区级联 | `.area-selector-container`（2270–2364），不能作为普通平铺下拉处理 |

Phoenix 已选项读值需要区分“已提交值”和搜索输入（2107–2129、2787–2809）：

| 读值候选 | 限制 |
| --- | --- |
| `.phoenix-button__content`（2112） | 排除占位文字 |
| `.phoenix-select__placeHolder`（2114–2115） | 不含 `.phoenix-select__placeHolder--show` 才是已提交状态的候选证据 |
| `.phoenix-select__selection, [class*="selectedValue"], [class*="selectedItem"], [class*="multiValue"], [class*="tag"]`（2118） | 必须收窄到当前控件；宽泛类名可能匹配装饰元素 |
| `.phoenix-select__calcEle`（2122） | 仅在已提交状态下作为辅助回读 |
| `.phoenix-select__input`（2110） | 可能是搜索词，不能单独证明选择成功 |

菜单可能渲染在表单外部 portal；竞品比较开菜单前后的列表来定位本次菜单，并在 `finally` 中关闭临时菜单（2270–2364）。独立实现仍须验证菜单与触发器关系，无法唯一关联时停止。带 footer 的下拉还存在确认阶段（4387），点击选项不等于提交完成。

页面状态探针区分 `/job/empty`、明确关闭文案、限制提示、`/form`、`/login` 与详情入口（1794–1852）。其目标验证含严格 origin、路径及职位参数检查（1194–1277），适合独立实现；其未知状态最终被当成过期（6585–6589）不采用。成功路径候选 `/form/friendly`（876、5794–5809）只作可见状态线索；我们不用 URL 子串判定成功，不监听或重放私有保存请求。

简历解析上传后，竞品会等待上传结束及表单稳定，再次发现上传器并重新识别（5598、6280–6444）。我们的实现应允许一次上传产生新的控件身份，保留解析前快照与确认项；不能沿用旧卡片索引直接覆盖。最终回读不应重新开下拉，避免改变用户选择。

## 智联校招网申

本模块与前两者存在重要差异：主要采用业务 API 获取 schema、组装资料快照、上传附件及回写，而不是 DOM 字段填写（1943–2028）。`getIdentifiedFields` 返回空分组（2278–2289）。因此，不能据此声称已经获得智联所有动态表单的 DOM 适配方案；该工作流仅覆盖特定校招网申产品，不能外推智联全部站点。

观察到的流程（2166–2258）：验证目标 origin → 探测详情页申请入口 → 检查重复/志愿配额 → 资料填写 → 有缺失项则留在核对状态 → 进入志愿选择页等待用户确认。已有投递或配额受限时也会进入志愿调整阶段，不能把它们计为新投递成功。

少量可复核页面事实：详情按钮 `.job-apply.job-banner__deliver__btn`（723、2051），后备入口 `.job-apply` 或可见的“立即投递”按钮（2030–2076）；志愿页路径 `/scrd/postprocess2`（724、2222、2252）。路径仅用于状态分类，不应自行拼接未经验证的跳转参数。详情入口的原生/ARIA 禁用状态及 `pointer-events` 会参与判断，缺失、禁用、来源变化应分开处理（2030–2087）。入口缺失直接判过期（2290–2296）的做法不采用。

独立实现以可见 DOM 为依据：手动登录 → 扫描当前页 → 核对资料与附件 → 填写 → 遇志愿、声明、校验或缺少字段则交还用户。没有可靠字段结构的页面返回不支持/待核对，不能猜测其后端 schema。竞品读取主窗口认证缓存来识别登录（2264–2274）也不采用；应用内浏览器只保留正常站点会话，让用户自行完成认证。

## 实施边界

1. 平台识别使用解析后的 HTTPS hostname 白名单与严格 origin；禁止 `url.includes(targetSite)`。页面跳转后重新验证信任边界。
2. 保持既有可见性、同源 frame、开放 Shadow DOM 边界。平台选择器是通用识别的补充，不能扩大采集范围。
3. 上传仅使用用户已导入本应用并明确选择的 PDF 简历或附件；资料识别与上传请求均不调用竞品服务。上传成功先回读文件与页面确认，再等待局部重绘并重定位。
4. 不采用竞品的登录界面隐藏/删除、强制手机登录、关闭页面、账号手机号采集、认证缓存读取、私有请求头提取、私有 API 回写或 OSS 上传协议。相关静态位置包括 Moka 2899–3025、北森 1278–1644、智联 792–835/1209–1255/1943–2028。
5. 不复制字段映射字典、资料精度修补规则或算法；日期维持用户原始精度，未提供的月日不得补造。协议、隐私声明、承诺、验证码及安全字段交给用户。
6. 本轮不自动提交、不自动选择志愿、不替用户接受声明。填写完毕与投递成功分别记录；明确显示缺失、歧义、待登录、职位关闭、配额限制和未知状态。
7. 选择器契约应使用不含个人信息的独立合成页面测试。实际站点后续仍需用户参与的手动登录、预览与回读验证；静态事实不能替代该验收。
