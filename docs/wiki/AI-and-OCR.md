# AI 与 OCR

## 模型配置与测试

桌面端和扩展提供 DeepSeek、Kimi、OpenAI、OpenRouter 模板。模型 ID 可改，使用平台正式 API 密钥；网页聊天订阅凭据不能代替 API 密钥。跨服务商域名切换时不复用旧密钥。

建议在桌面端保存并测试，再连接插件。直接配置在扩展的云端密钥仅保留浏览器会话，重启后可能需要重新保存。

思考模式可选自动、服务商默认或关闭深度思考。只有服务商支持对应参数时才选择关闭；该设置不保证所有模型响应速度一致。

选项匹配先用本地唯一规则；明确匹配和数值边界歧义都不需要模型请求。证件号、银行账号与私人联系方式等敏感值不发送给选项模型。普通字段 AI 默认只发标签及候选路径；仍需核对建议后填写。

网页 OCR 首次加载语言模型，后续串行复用本地进程；空闲五分钟、取消、故障或停服时回收。复用的是语言模型，不保存截图。

“保存并测试模型”经过鉴权本地网关向上游发送虚构字段，检查兼容 Chat Completions 响应及有效路径匹配，不用规则或缓存冒充成功。HTTP 200、空匹配或错误 JSON 均不足以证明协议成功。

一次成功只证明该时刻配置与测试输入可用，不保证其他模型、PDF 或所有网页。模型列表会变化，请在服务商控制台核对。

## 主动匹配

启用模型后，扫描先显示本地结果，随后异步请求未解决字段建议。自动模式仅发送标签、必要上下文和相关路径，不发送候选资料值；没有相关候选时不盲目请求。

建议需返回现有路径，通过字段、经历归属与置信度校验。人工修改、已填字段不被旧请求覆盖。填写仍由你启动。可关闭主动开关，或在高级工具中预览和请求建议；手动附带资料值需单独勾选。

网络与模型会增加等待，本地结果先完成。延迟取决于服务负载，不能承诺固定秒数；失败时本地匹配仍可用。

## OCR 与 PDF

- PDF 文字提取和 OCR 在本机进行，内置简体中文、繁体中文与英文模型。AI 解析需主动授权发送提取的简历原文，合并前核对。
- 网页 OCR 由主动点击触发，将可见截图发到本机桌面端，补充图片 / Canvas 标签。确认标签并绑定真实控件，DOM 标签优先，不按图片坐标盲点。
- 网页 OCR 不上传模型、不保存截图；过程中不要滚动或切页。嵌入式表单暂不使用整页截图 OCR。
- “重新扫描并学习已填内容”是本地差异与保存流程，不向模型发送读取的值。
