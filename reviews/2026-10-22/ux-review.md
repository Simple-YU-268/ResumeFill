# UX 走查报告 — 用户体验设计师

> **方法论声明**：本次为**代码走查 + persona 模拟**（基于 popup.html/popup.js、options.html/options.js、desktop/ui/index.html、desktop/ui/app.js、desktop-connect.js 的实际 DOM 结构与全部文案，逐流程推演渲染结果与状态流转），未进行真实浏览器截图走查。结论是强假设，需用真实用户测试验证。

## Persona 画像

```
PERSONA A（主 persona）
================
姓名: 林小满，22 岁女，应届本科生（上海）
处境: 秋招季，每天要在 5-8 个招聘网站重复填写同一份简历，手快断了
搜索词: "网申 自动填写 简历" → 看到这个项目 README 后下载
设备: Windows + Chrome，此前没装过"解压的扩展"
熟悉度: Low（不知道什么是 JSON、适配规则、配对码）
紧迫度: Days（这周要投 20 家）
主要恐惧: 填错信息被 HR 看到、简历数据被上传泄露、把网页表单搞乱

PERSONA B（对照 persona）
================
姓名: 老周，26 岁男，社招跳槽，有编程基础
依恋倾向: Avoidant 回避型——只要事实和开关，讨厌引导和废话
主要诉求: 数据不出本机、能审计、能导出、别替我提交
```

## Phase 0 — 抵达前

**林小满**："又是个要配置的玩意儿……README 说要装桌面端还要装扩展，行吧。它说本地存储，简历不会被传走吧？我就想要一个按钮，点一下，表单自己填好。别让我写代码。"

**相关性契约**：打开弹窗 3 秒内必须回答——①这是填简历的；②我的资料安全；③第一步点哪里。

## Phase 1 — 五秒测试（弹窗首屏）

**林小满独白**："『让简历，少填一次』——嗯，是干这个的，好。『本地存储』，看到了，安心一点。但是……第一个大按钮是『自动发现并连接桌面端』？我连了干嘛？不连能用吗？下面才是『扫描当前页面』。还有一行小字『先保存简历，再扫描招聘页面』——可我没保存过简历啊，去哪保存？哦，『管理简历与站点规则』……行，先点那个。"

```
ANALYST — 弹窗首屏
==================
Emotional state:  犹豫（relevance ✓ / trust ✓ / 行动路径不明）
Trust delta:      ↑（本地存储 badge + 页脚"不自动提交申请"免责说明，焦虑被接住一半）
LIFT:             Distraction ↑——桌面端连接卡（可选增强）排在主操作"扫描"之前；
                  Clarity ↓——「先保存简历」是纯文字提示，没有可点的引导入口
Cialdini active:  无（没有任何"已有 X 人使用"/演示/示例的社会认同）
Cialdini missing: Authority——"本地存储"是自说自话，缺一句可验证的承诺
Fogg:             M 高 / A 低（第一步动作被三个按钮分流）/ Prompt 有但错位
CTA reachable:    部分——主 CTA「扫描」可见，但对未保存简历的新手它是死路
```

**关键发现**：首屏回答了"是什么、安全吗"，但"第一步做什么"依赖用户自己推理出「管理简历与站点规则」=「先去保存简历」。且弹窗里的按钮叫「管理简历与站点规则」，而扫描时的报错文案写的是「请先打开**「管理简历 JSON」**保存简历」（popup.js:39）——**按钮名和报错指引对不上**，焦虑型 persona 在这一步会真的卡住。

## Phase 2 — 分流程走查

### 流程 A：扫描 → 核对

**林小满独白**："保存好了（在设置页对着一大坨 JSON 发了几分钟呆，幸好有『载入简历示例』）。回来点扫描……哦！出来一堆行，每行是网页上的字段名，旁边一个下拉框写着『工作 / 实习经历 第 2 条 · 公司』，能看懂的，不是英文路径，好评。最上面那行统计『通用识别 · 23 个字段 · 有资料 18 · 必填缺漏 2 · 待补经历 0』——必填缺漏 2！哪两个？我往下滑……哦它们被排到最上面了，还带星号，好。这个空着的下面有个灰框，鼠标放上去写着一大段话，什么『已识别 work.0.company』——work 点 0 点 company 是啥？我就知道我这一段没填。底下还有个『补充资料』的框突然出现了，我要写吗？写了存哪？"

```
ANALYST — 核对屏
================
Emotional state:  好奇 → 局部困惑
Trust delta:      ↑（人类可读标签 pathLabel() 是全局最大亮点：「教育经历 第 1 条 · 就读院校」，
                    完全兑现"让人核对"的承诺；未解决字段优先排序 + 必填置顶正确）
LIFT:             Clarity ↓——preview 框的三态 placeholder 文案过长且泄露实现细节
                  （"已识别 work.0.company，插件资料值为空"），JSON 路径出现在多处
                  面向新手的文案里（scope 区"对应 JSON 第几条经历"、学习面板"保存到本地 JSON"）
Cialdini active:  Commitment——逐行核对下拉框即是微承诺累积，设计天然正确
Fogg:             M 高 / A 中高 / Prompt ✗——「一键填充」按钮在整列字段下方，
                  23 个字段的表单要滚到底才能看到它
```

**具体观察**：
- **未解决优先排序**（popup.js:67-68，`required 未解决 → 可选未解决 → 已匹配`）实现正确且动机正确，是全流程最好的 UX 决策之一。
- **增量记忆**：重复扫描时 verified 字段显示「已重新回读一致，本轮跳过」——这是焦虑型 persona 最需要的安抚，极好。
- **draft 补充框**的出现逻辑（无值时才显示）聪明，但 placeholder 三态文案每态都是 30+ 字长句，扫读 impossible。
- 「记住匹配」按钮无任何前置解释——点了之后才告诉你"按域名、路径、表单结构记住"。新手不知道什么时候该点它，不点会怎样。
- 「补齐经历并重新扫描」按钮——"补齐"是产品内部概念（按适配规则点击页面上的"添加经历"按钮），文案对新手完全不可解码。

### 流程 B：填充 → 结果卡片 → 单字段重试

**林小满独白**："勾不勾『允许覆盖已有内容』？不勾吧，怕。点填充！……按钮都灰了，在填吗？填到第几个了？没动静啊……哦好了。『回读一致 17 · 保留 1 · 失败 2 · 未填 3』，下面卡片里两个红字：『毕业时间：填写失败』『期望薪资：值不一致』，各有一个『重试此字段』。点一下重试……成功了！变成『回读一致』。另一个还不行，出现了一个下拉框让我选网页里的真实选项，选了『15-20K』，点『填写并记住此选项』，过了。行，最后那句『请核对网页；未检查其他分页或服务器保存状态』——对，我自己再看一眼，提交是我自己点，这个分寸我喜欢。"

```
ANALYST — 填充与结果
====================
Emotional state:  焦虑峰值（填充进行中无任何进度反馈）→ 安心（结果卡片）
Trust delta:      ↑↑（结果卡片是全局信任最高点：状态分类清晰、失败行有重试、
                    选项失败时给出真实选项下拉 + 记住映射、"提交由你完成"边界清晰）
LIFT:             Anxiety ↓↓ 做得极好；但填充进行中的 0 反馈是 Anxiety ↑ 尖峰
Cialdini active:  Reciprocity（先干活再要确认）；Commitment（重试/记住选项=微承诺闭环）
Fogg:             重试按钮 = Facilitator 型提示，M 高 A 低时正确介入
缺陷:             ① cancelFill 在 run() 中被特意保持可用（popup.js:19），
                  却藏在折叠的「Agent 与高级工具」details 里——填充中想停的人找不到它；
                  ② 失败行若无已选路径则不渲染重试按钮，也没有"怎么办"的引导；
                  ③ 结果汇总被塞进 status 一大段多行文本（popup.js:130），
                  与结果卡片内容重复且更糊
```

### 流程 C：桌面端一键配对

**林小满独白**："桌面端装好了，界面上写着『本地服务在线』。设置页第一个大按钮『自动发现并连接桌面端』，点了……『正在发现本机桌面端…』然后『请在桌面端点击一次允许』——切过去，桌面上写着『Chrome 请求配对，允许后可读取/写回资料、使用模型与本地 OCR』，点允许。回来显示『已连接桌面端；以后打开插件可自动重连』。一次搞定，没让我复制什么码，这个比我想的顺。"

```
ANALYST — 配对流
================
Emotional state:  顺利，信任建立
Trust delta:      ↑（配对请求明示权限范围"可读取/写回资料、使用模型与本地 OCR"——
                    权限透明是全产品最强的信任信号；有拒绝按钮；超时后给出明确恢复路径
                    "请在桌面端确认后点击重新连接"）
LIFT:             Clarity ↑；Anxiety ↓
残留问题:         ① 90 秒配对轮询期间，扩展侧只有一行 status 文字，无倒计时；
                  ② 手动配对码入口 placeholder 是一段 JSON 字面量
                  （"粘贴 {\"kind\":\"resumefill-pairing\", …} 内容"），对降级用户是黑话，
                  好在已有"推荐使用上方自动连接"的引导稀释
```

### 流程 D：桌面管理页（连接状态 / 审计 / 更新）

**林小满独白**："三个卡片：本地 Agent 运行中、推理模式、已连接扩展 1。下面『扩展读取资料 · 14:32 · 客户端 a3f9…』——客户端后面那串是什么？我的电脑代号吗？更新这块有四个按钮：『一键更新并重启』『仅检查更新』『下载更新』『重启安装』……前两个我懂，后两个灰的什么时候能用？我一键更新的话还要不要点下载？算了点一键的吧。哦它不让我更，说『个人资料尚未保存，请先保存后再更新』——好吧，有道理，但你就不能在按钮旁边提前告诉我吗？"

**老周（对照）独白**："连接列表给我 browser 名、扩展版本、时间，行。审计只留了敏感操作、滤掉心跳，对。客户端 ID 截 8 位给我看没意义，我要看就给全，不然别显示。更新状态机文案每个阶段都覆盖了，包括失败时『可重试或到发布页手动下载』——但发布页链接呢？没给。凭据恢复那块的说明写得诚实：会备份、会撤销旧连接、会暂停 AI。这个我可以信。"

```
ANALYST — 桌面管理页
====================
Emotional state:  林小满=基本安心+局部困惑；老周=信任但嫌啰嗦
Trust delta:      ↑（凭据恢复板块的事前后果说明是模范文案；"密钥本机加密"位置标注好）
LIFT:             Clarity ↓——更新区四按钮并存，状态机对用户不透明
                  （available 才出现"下载更新"、ready 才出现"重启安装"，但
                  "一键更新并重启"与它们的关系从未解释）
Cialdini missing: Authority——"已是最新版本"之外无任何版本/发布信息佐证
Fogg:             更新按钮的 disabled 状态正确；但 checkUpdateEdits 的拦截
                  （未保存资料禁止更新）只在点击后以红色 notice 出现，无前置提示
审计:             activity 滤掉 heartbeat 正确；clientId 截断 8 位两头不讨好
                  （新手看不懂，老手嫌不全）
```

## Phase 3 — 结论

**林小满收尾独白**："填是真给我填上了，错的地方也告诉我了还让我重试，最后提交还是我自己点的——这个我挺感动。就是前面装的时候吓了我两跳：装扩展要开『开发者模式』它也没说为什么；还有到处都是 JSON 这个词，我又不是程序员。"

```
VERDICT（林小满）
-----------------
Confidence score:  7/10 — 边界声明诚实（不自动提交/本地存储/未检查服务器保存），
                   但上手期两处文案断点消耗了信任
Clarity score:     6/10 — 主流程清晰，概念层（JSON/适配/补齐/记住）对新手不可解码
Relevance score:   8/10 — 核心承诺"少填一次"完整兑现
Would I use:       Yes — 但第一次配置时差点放弃，靠"载入简历示例"救回来

Top 3 strengths:
1. 人类可读字段标签 + 未解决优先排序 + 必填置顶（LIFT:Clarity/Relevance 双赢，
   核对屏是产品的心脏，做对了）
2. 结果卡片：状态分类 / 失败行重试 / 真实选项下拉 + 记住映射 / "提交由你完成"
   （焦虑闭环：每个失败都有下一步，每个成功都有回读证据）
3. 配对流权限透明 + 恢复路径完备（90s 超时、凭据重建、配对码过期均有明确文案）

Top 3 weaknesses:
1. 新手期文案泄露实现细节：JSON 路径（work.0.company）、"适配规则"、"补齐经历"
   出现在面向第一用户的界面上；且报错指引与按钮名不一致（「管理简历 JSON」
   vs 实际按钮「管理简历与站点规则」）——这是唯一一个会让人真正卡死的点
2. 操作进行中零反馈：填充/扫描期间按钮全灰但无进度、无"正在处理第 N 个"，
   唯一的逃生门 cancelFill 被折叠进高级工具 details（代码特意保活它，UI 却藏了它）
3. 主 CTA 不可达 + 视觉平淡：长表单时「一键填充」需滚到底；通篇 DOM 无任何
   插画/空状态图形元素，与 AGENTS.md"趣味简洁插画风、突出扫描/核对/填写"
   的要求在结构层就没有落点（插画只能全靠 CSS，首屏空状态仅一行灰字）

The moment I almost left: 设置页打开看到一整屏 JSON 的那一刻——
                          全靠「载入简历示例」按钮续命
The moment I was most engaged: 填充后结果卡片逐行变绿、失败行点重试成功的那一刻
```

**对照（老周）**：Confidence 8/10，"审计、checkpoint 导出、学习面板默认不勾敏感项——这是懂行的设计。把 15 个高级按钮分个组、给我完整的 clientId，我就没意见了。"两个 persona 的需求**不冲突**，都指向"分层"：新手要藏，老手要全。

## Phase 4 — 建议（按优先级）

### 🔴 速赢（< 1 天，高影响）

1. **统一报错指引与按钮名** — Fold: 弹窗/扫描前 | Framework: LIFT:Clarity
   What: `popup.js:39` 的「管理简历 JSON」改为与实际按钮一致的「管理简历与站点规则」；更优做法是错误状态里直接给可点击入口。
   Why: 这是全产品唯一会让新手"找不到北"的死点。
   Expected: 首次配置流失率下降。

2. **填充/扫描进行中加进度与可见的取消** — Fold: 填充 | Framework: LIFT:Anxiety + Fogg:Prompt
   What: run() 期间在 status 区显示"正在填写第 N/M 个字段"；把 `cancelFill` 从高级 details 里复制一个到填充进行中状态旁（代码已为它保活，UI 只需露面）。
   Why: 焦虑峰值出现在"按钮全灰且无任何动静"的那几秒。
   Expected: 中途强制关弹窗/刷页面的行为减少。

3. **新手文案去实现化** — Fold: 多处 | Framework: LIFT:Clarity
   What: placeholder 里的 `work.0.company` 改为复用 pathLabel() 的人类可读文本；「对应 JSON 第几条经历」→「对应简历里第几段经历」；「补齐经历并重新扫描」→「自动添加缺失的经历卡片」。
   Why: persona 不认识 JSON 路径，每个黑话词都是一次微小的信任扣分。

4. **「记住匹配」加一句前置说明** — Fold: 填充栏 | Framework: Cialdini:Commitment
   What: 按钮旁 muted 小字："下次打开同页面自动沿用本次核对结果"。
   Why: 现在用户要点下去才知道它干嘛，承诺链断了。

### 🟡 重大改进（数天，高影响）

5. **首屏按状态分流** — Fold: 弹窗首屏 | Framework: LIFT:Distraction + Fogg
   What: 未保存简历时，首屏主视觉 = 一个主按钮「先录入我的简历」+ 插画空状态；已保存未扫描 = 「扫描当前页面」独大；桌面端连接卡降级为可折叠条目或仅在需要 OCR/资料同步时出现。
   Why: 现在三个按钮平铺，新手要自己推理状态机；AGENTS.md 要求"优先突出扫描、核对、填写"，当前 DOM 顺序（连接卡 → Agent 状态 → 主操作）与之相悖。

6. **填充栏常驻（sticky fillbar）** — Fold: 核对 | Framework: Fogg:Prompt
   What: 「一键填充已匹配字段 + 结果计数」吸底固定在弹窗可视区内。
   Why: 23 字段表单滚到底才见 CTA，M/A 都到位时 Prompt 缺席。

7. **更新区收敛为"一个主按钮 + 状态文本"** — Fold: 桌面总览 | Framework: LIFT:Clarity
   What: 默认只显示「一键更新并重启」；下载/重启按钮出现时用一句话说明当前处于哪一步（"已下载完成，点击重启完成安装"）；高级分步操作收进详情。
   Why: 四个按钮的概念关系（一键 vs 分步）从未向用户解释。

8. **空状态与插画落地** — Fold: 全部 | Framework: AGENTS.md 合规 + Cialdini:Liking
   What: 为"未扫描/未连接/无配对请求/审计为空/全部回读一致"五个空状态各配一个同造型体系的简洁插画（哪怕 inline SVG）；结果卡片全绿时给一个明确的"完成"视觉。
   Why: 当前 DOM 零插画元素，"趣味简洁插画风"只存在于 CSS 可能性里；空状态恰是新手最需要安抚的时刻。

### 🔵 战略机会（需规划，复利）

9. **首次使用三步向导**（录入资料 → 连接桌面端（可跳过）→ 去招聘页扫描），完成后不再出现——把当前散落在三个界面里的概念（简历/配对/扫描）串成一条线。预计能把上手时间从 ~15 分钟压到 ~5 分钟。

10. **「结果 → 学习」闭环引导**：结果卡片存在"未填"字段时，直接给出「重新扫描并学习已填内容」的入口（该按钮目前由 JS 动态插在扫描键旁，与主操作平级，位置和语义都模糊），把"这次没填上的，下次自动会填"这个最强留存卖点显性化。

11. **高级工具分区命名**：15+ 按钮按「自动 Agent / AI 建议 / 核对工具 / 排障」四组加小标题；桌面端审计列表给完整 clientId 的展开查看（hover/点击），同时满足两个 persona。
