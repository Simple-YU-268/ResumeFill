## 0. 版本校准：你审查的基线不是 0.18.0

工作区实际状态：**package.json、manifest.json、README 均为 0.24.1**（2026-10-22，"开发测试版，尚未正式发行"）。0.16（安全加固）、0.17（核对与连接 UX）、0.18（应用内自动更新）之后，已陆续发了 0.19（一键更新）、0.20（自动发现配对 + iframe/51job 适配）、0.21（学习已填内容）、0.22（统一插画视觉 + Wiki）、0.23（桌面↔插件差异同步）、0.24（家庭成员资料）。**`dist/` 里躺着 0.13 到 0.24.1 共 12 个历史构建目录**——发布卫生本身也是一个信号。

我无法联网核实 GitHub Releases 上的最新正式版；CHANGELOG 自述 0.24.1"真实报考页面暂不可用，尚未复测或正式发行"，所以最新正式版应是 0.24.0 或更早。**这本身就是审查发现的第一个问题：版本叙述混乱**（用户以为是 0.18.0，仓库已是 0.24.1 开发版），对外沟通材料与用户认知存在断层。

## 1. 产品定位与核心流程：闭环已经成立，但断点在"安装前"

定位清晰且克制：**本地优先、人工核对、不自动提交**——这三条红线贯穿代码（Agent 无提交工具、密码/验证码全程排除）与文档。核心用户流程在 0.23–0.24 之后真正闭环了：

```
整理资料（桌面可视化/JSON/PDF导入）
  → 配对连接（0.16 一次性配对码 → 0.20 自动发现）
  → 扫描 → 核对（0.17 中文标签、未解决项置顶、单一主按钮）
  → 填写 → 回读验证（结果卡 + 单字段重试）
  → 学习已填内容（0.21）→ 差异同步回桌面（0.23）
  → 下次扫描用新资料
```

**这个"填过 → 学会 → 同步 → 下次少填"的复利循环是产品最有价值的资产**，且每一步都有隐私护栏（修改项默认不选、敏感项单独确认、学习前备份、学习不发 AI）。

但流程的真正断点在用户还没进入循环之前：

| 断点 | 证据 |
|---|---|
| 扩展只能开发者模式加载 | docs/wiki/Getting-Started.md：启用开发者模式→加载解压目录。对秋招学生目标用户，这是最高的安装流失点 |
| 安装程序未签名 | README.md：SmartScreen 拦截 + 手动核对 SHA256，冷启动信任成本高 |
| 桌面更新后扩展不会自动更新 | CHANGELOG 0.19.0 自述："After desktop updates, reload the unpacked Chrome/Edge extension"——0.18 做的自动更新只覆盖桌面端，**双端版本漂移是新发的技术债**，0.24.1 的版本戳协议检查（旧脚本阻断）正是这个债的利息 |
| 0.24.1 未复测真实页面 | CHANGELOG 自述"真实报考页面暂不可用，尚未复测"——一个核心流程改动（版本阻断 + Layui 重绘）压在未验证状态 |

## 2. 隐私卖点的成色：真，但审查节奏已经掉队

隐私承诺在代码层面是实的，不是 marketing：

- safeStorage/DPAPI 加密凭据、失败关闭不回退明文（0.16）；
- AI 默认关闭、主动匹配只发标签与候选路径、`shareValues` 默认不勾（popup.html 高级区）、PDF 解析需显式勾选同意；
- 网页 OCR 截图只发本机回环端点、内存处理、不留存（PRIVACY-REVIEW 末节）；
- 模型密钥不进扩展、扩展令牌与云端密钥分离。

**但 PRIVACY-REVIEW.md 停在 v0.23.0（2026-10-21）。0.24.x 引入了两个新的敏感面未经审查记录**：

1. **家庭成员身份证号自动记忆**（`family.father.idNumber`，默认关闭但仍属新增高敏数据通道）；
2. 差异同步中家庭资料全部按敏感项核对的实现，没有进审查文档。

一个以"数据不出本机"为唯一信任状的产品，**隐私审查滞后于发版 = 卖点在静默贬值**。这不是功能问题，是发布流程的制度缺口。

## 3. 功能缺口清单（0.16–0.18 之后到现在的真实状态）

**已补上的**（不用再做）：自动更新、配对体验、结果卡重试、学习闭环、双端同步、视觉统一、wiki 文档体系。0.16–0.18 三件套是正确的基础设施投入。

**仍然缺口的**：

1. **分发闭环缺失**（最大缺口）：商店未上架、安装包未签名、扩展更新靠手动 reload。0.18 的自动更新只完成了一半——桌面端能自己更新，扩展不能。
2. **发布无回看**：仓库里没有任何采用率/成功率度量机制。本地优先不能装遥测（装了就是定位自杀），但**本地统计仪表板**（扫描次数、填写成功率、学习采纳率，全部留在本机）是可行的。现在的发布纪律是"测试通过即发布"，不是"发布后被验证"。
3. **站点适配靠手写 JSON**：FEATURES-0.2.md 自述"真实招聘站点仍需结合页面编写配置"。适配规则是产品的护城河也是产能黑洞——每接一个新站都是手工活。
4. **popup 高级工具区有 15+ 个按钮**（popup.html `agentTools` 区：Agent 6 个 + 工具 7 个 + OCR 2 个）。0.17 折叠了它们，但认知负担只是被藏起来，没有被削减。
5. **`autoAI` 复选框默认勾选**（popup.html `<input id="autoAI" type="checkbox" checked>`），与 options 页"AI 默认关闭"的叙述存在 UI 层面的张力——虽然未配置模型时不发请求，但默认勾选在向用户传递错误信号。
6. **地区词典冻结在 2023-06-30**（FEATURES-0.6.md），数据源已停更——是一个会随时间变质的隐性依赖。

## 4. 下一版本建议（按机会成本排序）

**总判断：0.24.1 还没复测发行，下一件最该做的事不是任何新功能，而是把"验证→发布"闭环走完。** 以下排序以此为先决条件。

| 优先级 | 条目 | 假设 | 验证方式 | 判定线 | 机会成本（批准它 = 推迟什么） |
|---|---|---|---|---|---|
| **P0** | **先把 0.24.1 复测发行为 0.24.1 正式版或砍回退** | 若真实报考页面复测通过，则版本戳阻断机制在真实环境不误伤 | 在目标报考页面跑完整扫描→填写→回读 | 真实页面无版本误报；Layui 四种组合场景全过 | 推迟一切新功能——但未验证的版本本身是最大的功能负资产 |
| **P1** | **隐私审查制度化 + 补审 0.24.x** | 若每次 minor release 强制重审，则"本地优先"卖点可持续主张 | PRIVACY-REVIEW.md 日期与发版日期对齐；0.24 家庭身份证自动记忆有专门章节 | 下个版本发布时审查不滞后 | 推迟 P2 一周；不做的代价是卖点静默贬值 |
| **P2** | **扩展上架 Chrome/Edge 商店（大赌注，先验证）** | 若上架商店，则安装完成率显著上升、且桌面更新后扩展可随商店更新消除版本漂移 | 先用 Edge Add-ons（审核门槛低）试点；记录上架前后安装转化率 | 安装引导步骤从 5 步降到 2 步；扩展随商店自动更新 | 推迟 P3/P4；风险：商店审核可能要求权限说明与隐私政策页面，需预留 |
| **P3** | **本地成效统计仪表板（不外发）** | 若用户能看到"本机"扫描/填写成功率，则学习闭环的复利对用户可见、且发布回看有数据 | 桌面端新增只读统计页；数据只写本机 | 上线后开发者自己看：填写一次通过率、学习采纳率 | 推迟 P5；这是"发布对结果负责"的唯一可行度量路径 |
| **P4** | **签名安装程序** | 若 SmartScreen 拦截消除，则下载→安装转化上升 | 观察发行页下载量与 issues 中"无法安装"反馈 | SmartScreen 警告消失 | 有成本（证书费用）；与 P2 二选一优先 P2 |
| **P5** | **裁剪高级工具区 + autoAI 默认改为不勾** | 若默认不主动请求 AI 与叙述一致、且高级按钮按使用频率重排，则新用户首扫成功率上升 | 找 5 个未用过产品的目标用户做 10 分钟走廊测试 | 首次扫描→填写完成无需打开高级区 | 小赌注，直接灰度 |

### 不做清单（维持并记录理由）

- **不做自动提交/代填验证码/附件代传**——定位红线，已在代码层强制执行，复审条件：无。
- **不做云同步/账号体系**——会摧毁"数据不出本机"的唯一信任状；复审条件：定位本身改变。
- **不做通用任意网站自动填写承诺**——COMPETITOR-RESEARCH 显示连商业竞品也只能服务端兜底；我们走"明确适配 + 人工核对"路线，不追这个幻象。
- **不做竞品功能照搬**——COMPETITOR-RESEARCH.md 的 REA 方法（独立实现 + 不采用破坏唯一性的策略如"缺月日补 1"）是对的，继续。

### 附带发现（工程卫生）

- `dist/` 累积 12 个历史版本构建目录（0.13–0.24.1），建议只保留当前版 + 归档策略；根目录 80+ 个文件平铺，测试文件与产品文件混杂，下一次重构窗口值得做一次目录分层。

---

**一句话结论**：核心流程闭环在 0.23–0.24 已经真正成立，产品的瓶颈早已从"功能不够"转移到"装不上、发不出、没回看"。下一个版本最值钱的动作是：发行 0.24.1 → 补隐私审查 → 冲商店上架。功能面唯一值得做的是本地统计仪表板，其余都是机会成本为负的加法。
