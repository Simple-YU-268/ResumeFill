# ResumeFill 品牌与创意评估（下一轮开发前）

评估日期：2026-10-23。评估范围：`theme.css`、`visual.js`、`buddy.svg`、`popup.html`、`desktop/ui/index.html`、`docs/wiki/`、`README.md`、`manifest.json`、`docs/STORE-SUBMISSION.md`、历史评审（`reviews/2026-10-22/`、`docs/reviews/`）。评估基准：保持本地优先、可信赖、不焦虑的产品气质；遵守 AGENTS.md「趣味、简洁的插画风格，突出扫描 / 核对 / 填写」的约定。

## 一、品牌识别度与记忆点

**已有的强资产：**

- `buddy.svg` 是真正的品牌角色：简历纸身体、小手小脚、腮红、举着蓝色对勾牌、柠檬黄太阳和星号点缀。用色与 `theme.css` token 严格对齐（墨绿描边 `#283F3C`、主绿 `#3e6758`、柠檬黄 `#F6D977`、蓝 `#657FD3`、桃色腮红 `#F5B5A0`），桌面端、弹窗、设置页三端共享——共享视觉资源的约定已经落实。
- 核心口号「少填一点，多一点可能」在 README、桌面欢迎区、Wiki 首页三处一致，是稳定的记忆锚点。
- 「扫描 → 核对 → 填写」三步旅程条（journey）在桌面端和弹窗重复出现，把产品方法变成了视觉仪式，这是比插画更持久的识别。

**识别短板：**

1. **扩展没有图标。** `manifest.json` 没有 `icons` / `action.default_icon` 字段，工具栏里显示的是浏览器默认拼图块。这是日常曝光量最大的品牌触点，目前是空白的，也是商店上架的硬性门槛。
2. **双标识并存。** 桌面端 brand-mark 是黄色方块里的字母「R」，与 buddy 插画没有任何造型关联。用户看到两套识别，记忆被稀释。
3. **名字有三个版本。** README 用「ResumeFill Agent」，manifest 用「简历快填 · ResumeFill」，弹窗标题是「简历快填」，桌面侧边栏是「专用网申 Agent」。品牌名、产品名、角色定位混在一起。
4. **buddy 只有一个姿势。** 单一表情撑不起一个「搭档」角色；目前它更像一张贴纸而不是角色。

## 二、插画的情感设计是否足够

不足。buddy 目前只出现在三个「门口」位置（桌面欢迎区、弹窗 header、设置页 header），是迎宾员，不是全程搭档。真正情绪浓度高的时刻——扫描进行中、回读一致、部分失败、学习到新内容——它全部缺席。整个产品**零动效**（`prefers-reduced-motion` 降级已就绪，说明基建是好的，只是没有内容可降）。

文案层面情感设计其实已经到位：「让小搭档帮你识别、匹配和填写。每一步，都由你确认」准确传达了本地优先和人在环中的气质，不催促、不制造 FOMO。缺的是视觉与这些关键时刻的接应。

情感设计的正确方向不是「更活泼」，而是「有陪伴感」：buddy 应该在用户等待时陪着看、在成功时一起松口气、在失败时一起检查——这恰好就是「不焦虑」气质的视觉化。

## 三、空状态 / 成功时刻 / 错误时刻的创意空间

| 时刻 | 现状 | 空间 |
| --- | --- | --- |
| 空状态 | 纯文字占位（`#fields:empty::before`、「暂无待确认的配对请求」、「尚无统计」），位置正确但无插画 | 每个空状态配一个小幅 buddy 场景（举放大镜的空字段区、抱着空收件箱的配对区），把「空」从缺陷变成引导 |
| 成功时刻 | 结果卡是纯文字统计（「回读一致 15 · 保留 · 失败 · 未填」）；桌面「本机填报成效」只有计数 | 全量回读一致时 buddy 举对勾牌亮相 + 一句克制祝贺；部分失败时换成「一起来检查」姿势。不撒花、不弹全屏——与工具气质一致 |
| 错误时刻 | 文案技术上准确但偏工程口吻（「操作失败：…」、`RF_AGENT_*` 错误码直出） | 不改错误码和内容，加一层温和的人话外壳 + 固定的下一步动作按钮。buddy 出现一次即可，错误反复出现时不要重复动画（避免打扰感） |

「本机填报成效」卡片是最被低估的情感资产：它不联网、只在本机，本身就是隐私承诺的实体化。把它从「计数器」升级为「小搭档的工作记录」（本周帮你核对了 N 个字段、学习了 M 条新答案），既有人味又强化信任叙事。

## 四、商店上架视觉资产缺口

`docs/STORE-SUBMISSION.md` 已覆盖权限与隐私声明，视觉资产侧缺口：

- **图标（硬性）**：16 / 32 / 48 / 128 PNG 四尺寸。可直接从 buddy 提取：128 用 buddy 头像或举对勾牌的胸像；16px 需单独简化为可辨识的剪影（小脸 + 对勾），不能直接缩放大图。
- **截图（1280×800，1–5 张）**：现有 `docs/images/desktop-overview.png`、`profile-editor.png` 可作底，但商店截图需要叙事编排（见方向 5）。必须用合成资料重新录制，遵守隐私审查约定。
- **小宣传砖（440×280）**：buddy + 口号 + 三步旅程条即可，是品牌世界的浓缩海报。
- 桌面安装包尚无图标约定检查；Electron 图标与扩展图标应出自同一套 buddy 剪影，保证开始菜单、工具栏、商店三处一致。

## 五、下一轮创意方向清单（按影响力排序）

### P0 — 扩展图标系统（ buddy 剪影，4 尺寸）
上架硬性要求 + 日常曝光最高的触点，成本最低。同时统一 Electron 安装包图标。附带解决双标识问题：brand-mark 的「R」方块替换为 buddy 小头像或同一剪影，全产品只剩一套识别。

### P1 — Buddy 状态家族（5–6 个姿势，静态 SVG 先行）
为关键时刻各画一个姿势：**扫描**（举放大镜）、**核对**（拿清单打勾）、**填写中**（握笔写字）、**完成**（举对勾牌 + 闭眼笑）、**需要人工**（挠头指向某处）、**空状态**（挥手等待）。延续现有描边和配色体系，纯静态 SVG，零性能成本，CSP（`connect-src 'none'`、`script-src 'self'`）友好。接入点已在：`visual.js` 统一注入，只需把固定的 `buddy.svg` 换成按场景选图。

### P2 — 成功时刻的温和庆祝
结果卡全量回读一致时，buddy「完成」姿势出现在结果卡左上角 + 一句文案（如「N 个字段都核对无误，最后一步交给你」）。部分失败时用「需要人工」姿势 + 「M 个字段想请你看看」。用 CSS 一次性入场动画（<400ms），已被 `prefers-reduced-motion` 媒体查询覆盖。明确不做：全屏撒花、音效、计数滚动动画——都与不焦虑气质冲突。

### P3 — 空状态插画系统
把 4–5 处纯文字空状态换成「小幅插画 + 一句话 + 一个动作」结构。素材复用 P1 的姿势家族，边际成本低。这是用户首次使用时（尚未保存资料、尚未配对）的第一印象，直接影响「三步开始」的完成率。

### P4 — 商店截图叙事（5 张序列）
按真实旅程编排：① 桌面欢迎区（「少填一点，多一点可能」+ buddy）② 整理资料（可视化编辑器）③ 扫描核对（弹窗字段匹配，突出「每一步由你确认」）④ 填写回读（结果卡 + 温和庆祝）⑤ 隐私承诺（「资料保存在本机，申请提交由你完成」）。全部用合成资料录制；每张配一行图说，图说就是 README 里已有的句子，保证叙事口径一致。

### P5 — 「本机填报成效」人格化
把计数卡片升级为小搭档的工作记录：累计核对字段数、学习答案数，配 buddy 姿势和一句人话（「这周帮你核对了 47 个字段」）。明确边界：不加连续打卡、等级、勋章等游戏化机制——工具产品的留存靠好用，不靠上瘾，且与本地优先气质冲突。

### P6 — 错误文案的人话外壳
为 `RF_AGENT_*` 等错误码各配一句温和解释 + 固定下一步（重试 / 检查连接 / 重新扫描），错误码保留在末尾供排障。buddy 在首次出现错误时以「需要人工」姿势出现一次，同会话重复错误不再展示插画。只改文案层，不碰错误分类逻辑。

### 后置 — 彩蛋与季节主题（明确不建议本轮做）
Konami 式彩蛋、节日皮肤对这类工具是负资产：增加测试面、与「可信赖」叙事相悖、且分散上架前的精力。等品牌角色家族（P1）落地、用户真的对 buddy 产生感情后再考虑，届时一个「连续点击 buddy 三次它会眨眼」的小彩蛋成本几乎为零。

## 六、约束与风险

- **CSP 限制**：桌面端 `connect-src 'none'`、`script-src 'self'`——所有趣味只能用内联 SVG + CSS 动画，不能引入动画库或远程资源。这反而是好事，天然限制规模。
- **性能**：弹窗 620px 宽、每次打开即时渲染；所有插画保持单文件 <5KB SVG，`pointer-events:none` + `aria-hidden` 维持现状，不干扰屏幕阅读器和字段核对主任务。
- **动效降级**：`@media (prefers-reduced-motion: reduce)` 已全局禁用过渡，新动画只需遵守同一查询，无需额外开关。
- **隐私**：截图、宣传图一律合成资料；buddy 插画不含任何用户数据；「本机填报成效」保持只含计数、不外发的现有承诺。
- **发布卫生**：图标加入 manifest 后需纳入 `version:check` / 构建检查；商店资产建议放入 `docs/store/` 与源码一起版本管理，避免只存在于某次提审的本地机器上。
